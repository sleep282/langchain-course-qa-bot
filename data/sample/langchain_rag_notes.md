## 1. 什么是 LangChain

LangChain 是一个用于开发大语言模型（LLM）应用的开源框架。它把"模型调用、提示词、文档加载、向量检索、记忆、工具调用"等环节抽象成可拼接的组件（Chain / LCEL），让开发者可以像搭积木一样组装出复杂的 AI 应用。

LangChain 的核心概念包括：Model I/O（模型与提示词）、Retrieval（检索，对应 RAG）、Chains（链）、Agents（智能体）、Memory（记忆）。

## 2. 什么是 RAG

RAG 全称 Retrieval-Augmented Generation，即"检索增强生成"。它的思路是：在让大模型回答问题之前，先从用户自己的私有文档库里检索出与问题最相关的若干片段，把这些片段和问题一起塞进提示词，再交给大模型生成答案。

RAG 解决了大模型的两个典型痛点：
1. **知识过时**：大模型只训练到某个时间点，不知道企业内部/课程最新资料；
2. **幻觉**：没有依据时容易编造。RAG 让答案"有据可查"。

## 3. RAG 的典型流程

一个标准 RAG 应用分为"离线索引"和"在线问答"两个阶段：

**离线索引阶段**：
1. 文档加载（Document Loader）：读取 PDF、Word、网页等；
2. 文本切分（Splitter）：把长文档切成合适大小的 chunk；
3. 向量化（Embedding）：把每个 chunk 转成向量；
4. 入库（Vector Store）：把向量存入 Chroma / FAISS / Milvus 等向量库。

**在线问答阶段**：
1. 用户提问；
2. 把问题也向量化，到向量库做相似度检索，取出 Top-K 相关片段；
3. 把片段和问题拼成 Prompt；
4. 调用大模型生成最终答案。

## 4. 常用组件说明

- **Embedding 模型**：把文本映射成向量。本项目默认使用中文开源模型 `BAAI/bge-small-zh-v1.5`，本地运行、免费。
- **向量数据库**：本项目使用 ChromaDB，纯本地文件，无需启动额外服务。
- **大模型**：通过 OpenAI 兼容接口接入，可切换 DeepSeek、豆包、OpenAI、Kimi 等。
- **文本切分器**：RecursiveCharacterTextSplitter，按中文标点递归切分，chunk_size 默认 500，overlap 默认 80。

## 5. 常见面试/作业考点

- RAG 与微调（Fine-tuning）的区别：RAG 适合知识频繁更新、需要引用出处的场景；微调适合改变模型风格、输出格式或领域能力。
- chunk 大小如何选择：太大引入噪声，太小丢失上下文，课程问答一般 300~800 字较合适。
- 如何提升检索效果：更换更强的 Embedding 模型、加入重排序（Rerank）、使用混合检索（关键词 + 向量）。
